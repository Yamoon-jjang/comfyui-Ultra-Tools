Ultra Tools Image + PiD 메뉴얼

1. 노드 개요
Ultra Tools Image + PiD는 Krea 2, Z-Image, Anima, Qwen Image 계열의 이미지 생성과 선택적 PiD 업스케일을 한 노드에서 처리합니다.

주요 목적:
- diffusion model / text encoder / VAE 선택
- Positive / Negative conditioning 생성
- 동적 model-only LoRA 적용
- 기본 KSampler 이미지 생성
- 필요할 때만 통합 PiD 업스케일 실행
- 영문 UI에서는 `Original Image` / `PiD Image`, 한글 UI에서는 `원본 이미지` / `PiD 이미지` 두 출력 제공

노드 내부 식별자는 `UltraImagePiD`입니다.

예제 워크플로우:
- `이미지 워크플로우/Ultra_Image_AIO_Simple.json`

업데이트할 때는 기존 `comfyui-Ultra-Tools` 폴더를 삭제한 뒤 새 버전을 설치하십시오. 이전 버전에서 저장한 워크플로우와의 호환은 보장하지 않습니다.


2. 출력 구조
출력은 두 개입니다.
- 영문 UI: `Original Image` / `PiD Image`
- 한글 UI: `원본 이미지` / `PiD 이미지`

제거된 출력:
- latent
- model
- clip
- vae
- positive
- negative

따라서 추가 출력 표시/숨기기 버튼도 없습니다.

PiD OFF:
- `Original Image` = 기본 생성 원본 결과
- `PiD Image` = 원본 이미지를 그대로 전달하는 passthrough 결과

PiD ON:
- `Original Image` = 기본 생성 원본 결과
- `PiD Image` = PiD 업스케일 후 원본의 명암·색상을 자동으로 맞춘 최종 결과

PiD ON에서만 ComfyUI `Transfer Color`와 동일한 `reinhard_lab / per_frame / strength 1.0` 방식을 노드 내부에서 자동 적용합니다. 별도 색상 보정 노드를 연결하거나 추가 커스텀 노드를 설치할 필요가 없습니다. 원본 이미지를 덮어쓰지 않고, PiD가 만든 전체적인 공간 구조와 디테일을 대체로 유지하면서 프레임별 전역 Lab 명암·색상 통계를 원본에 맞추는 방식입니다.

따라서 원본/최종 결과 비교가 가능하고, 얼굴 디테일러·SeedVR2 업스케일·Preview Image·Save Image 등 일반적인 후속 이미지 노드에는 필요에 따라 `Original Image` 또는 `PiD Image`를 연결하면 됩니다. 보통 최종 사용용으로는 `PiD Image` 출력 하나만 연결해도 됩니다.


3. 기본 사용 순서
1) `positive_prompt`에 STRING을 연결합니다.
2) `model_family`을 선택합니다.
3) diffusion model / text encoder / VAE를 선택합니다.
4) width / height / batch / seed / sampler 설정을 정합니다.
5) 필요하면 LoRA를 추가합니다.
6) PiD가 필요 없으면 `PiD 업스케일` 토글을 OFF로 둡니다.
7) PiD가 필요하면 `PiD 업스케일` 토글을 ON으로 바꾸고 PiD 설정을 조정합니다.
8) 필요에 따라 `Original Image` 또는 `PiD Image` 출력을 후속 이미지 노드에 연결합니다.


3-1. PiD ON 전에 준비해야 하는 두 종류의 text encoder
이 노드는 기본 이미지 생성과 PiD 업스케일에서 서로 다른 text encoder를 사용합니다. PiD를 ON으로 사용할 때는 아래 두 종류가 모두 필요합니다.

1) 화면의 `text_encoder`
- 기본 이미지 생성 모델의 프롬프트를 인코딩합니다.
- 현재 `model_family`에 맞는 Qwen3-VL, Qwen Image, Lumina2, Stable Diffusion 계열 등의 text encoder를 사용자가 화면에서 선택합니다.
- 이 선택은 메인 원본 이미지 생성 단계에 적용되며 PiD 전용 Gemma encoder를 대신하지 않습니다.

2) 화면에 표시되지 않는 PiD 전용 text encoder
- PixelDiT PiD 모델의 프롬프트 conditioning을 만들기 위해 `gemma_2_2b_it_elm` 계열을 별도로 사용합니다.
- 사용자가 잘못된 PiD encoder를 선택하는 것을 막기 위해 별도 선택 메뉴를 표시하지 않으며, PiD가 ON일 때 노드가 자동으로 찾습니다.
- 화면에서 Qwen3-VL 계열 text encoder를 정상적으로 선택했더라도 PiD ON에는 Gemma ELM 파일이 추가로 필요합니다.

두 종류의 파일은 모두 아래 폴더에 둡니다.
- 일반 설치: `ComfyUI/models/text_encoders/`
- Windows Portable 예: `ComfyUI_windows_portable/ComfyUI/models/text_encoders/`

PiD용으로 아래 파일 중 하나 이상을 준비하십시오.
- 권장: `gemma_2_2b_it_elm_fp8_scaled.safetensors`
- 대안: `gemma_2_2b_it_elm_bf16.safetensors`

자동 탐색 우선순위는 FP8 scaled → BF16 → 파일명에 `gemma_2_2b_it_elm`이 포함된 기타 후보 순서입니다. 일반적으로 FP8 scaled는 BF16보다 파일 크기와 메모리 부담이 작아 우선 사용됩니다. 파일을 실행 중에 새로 복사했다면 ComfyUI를 재시작하거나 모델 목록을 새로고침하십시오.

PiD가 OFF이면 PiD 전용 Gemma encoder를 검사하거나 로드하지 않으므로 메인 이미지 생성용 text encoder만 있으면 됩니다.


4. 지원 모델 계열
`model_family`은 아래 네 계열을 지원합니다.
- Krea 2
- Z-Image
- Anima
- Qwen Image

노드는 model_family에 따라 CLIP type, latent 생성 방식, 필요한 model sampling wrapper를 내부에서 결정합니다.

현재 주요 내부 규칙:
- Krea 2: Krea2 CLIP 계열, EmptyLatentImage
- Z-Image: Lumina2 CLIP 계열, EmptySD3LatentImage, AuraFlow sampling shift 적용
- Anima: Stable Diffusion CLIP 계열, EmptyLatentImage
- Qwen Image: Qwen Image CLIP 계열, EmptySD3LatentImage, AuraFlow sampling shift 적용

model_family과 실제 diffusion model / text encoder가 맞지 않으면 로드 단계에서 오류가 발생할 수 있습니다.


5. 기본 이미지 생성 입력

5-1. positive_prompt
- STRING 입력입니다.
- 빈 문자열도 허용합니다.
- 입력 문장을 노드가 임의로 다시 쓰지 않습니다.

5-2. diffusion_model
메인 이미지 생성에 사용할 diffusion model입니다.

5-3. text_encoder
현재 model_family의 기본 이미지 생성에 맞는 text encoder를 선택합니다. 이 화면 항목은 메인 원본 이미지 생성용이며 PiD 전용 encoder 선택란이 아닙니다. PiD ON에서 별도로 필요한 Gemma ELM 파일과 저장 위치는 `3-1. PiD ON 전에 준비해야 하는 두 종류의 text encoder`를 참고하십시오.

5-4. vae_name
메인 sampled latent를 원본 이미지(`Original Image`)로 decode할 VAE입니다.

중요:
이 버전은 `Original Image` 출력을 항상 제공하므로 PiD가 ON이어도 메인 `vae_name`을 실제로 로드해 원본 이미지를 디코드합니다. 이후 PiD가 ON이면 별도로 PiD 결과(`PiD Image`)를 추가 생성합니다.

5-5. width / height
기본 이미지 생성 해상도입니다.
이 노드는 최종 실행 단계에서 width / height가 8의 배수인지 직접 검사합니다. 8의 배수가 아니면 core latent에서 조용히 잘리는 값이 생기지 않도록 샘플링 전에 명확한 오류를 표시합니다.
PiD ON일 때 PiD target은 이 실제 생성 해상도의 4배를 사용합니다.

예:
- 1152 × 896 → PiD target 4608 × 3584
- 896 × 1152 → PiD target 3584 × 4608
- 1024 × 1024 → PiD target 4096 × 4096

5-6. batch_size
기본 이미지 생성 batch입니다. PiD ON이면 같은 batch 수가 PiD 단계에도 전달되므로 큰 해상도와 높은 batch는 VRAM 사용량을 크게 늘릴 수 있습니다.
PiD를 사용할 때는 특별한 이유가 없다면 batch 1을 권장합니다. UI tooltip에도 같은 주의가 표시됩니다.

5-7. seed
메인 KSampler seed입니다. PiD 단계도 같은 seed 값을 사용합니다.

5-8. steps / cfg / sampler_name / scheduler / denoise
기본 이미지 생성용 샘플링 설정입니다. PiD 전용 샘플링 설정과는 별개입니다.


6. Negative 설정
`negative_mode`는 두 방식을 지원합니다.

1) `zero positive conditioning`
- positive conditioning을 ConditioningZeroOut으로 변환해 negative로 사용합니다.

2) `encode negative text`
- `negative_prompt`를 같은 메인 CLIP으로 별도 인코딩합니다.

`negative_prompt`는 두 번째 방식을 선택했을 때 메인 원본 이미지 생성에 사용됩니다.

PiD 단계의 네거티브 처리:
- 사용자가 입력한 `negative_prompt`는 PiD 단계에는 전달되지 않습니다.
- PiD 단계는 PixelDiT 기본 흐름에 맞춰 PiD positive text conditioning을 `ConditioningZeroOut`한 값을 negative로 사용합니다.
- PiD CFG는 내부 `1.0` 고정입니다.
- 따라서 현재 구조에서 `negative_prompt`는 `Original Image` 생성에 영향을 주지만 PiD 단계의 별도 negative text로 사용되지는 않습니다.


7. 동적 LoRA
노드 하단의 `＋ LoRA 추가` 버튼으로 필요한 만큼 LoRA 행을 추가할 수 있습니다.

각 LoRA 행:
- 활성/비활성
- LoRA 파일 선택
- strength 조절
- 우클릭으로 위/아래 이동
- 개별 삭제

적용 방식:
- model-only LoRA입니다.
- text encoder에는 적용하지 않습니다.
- 화면에 표시된 순서대로 적용합니다.
- 정상 UI 저장값은 각 행의 `order`를 사용합니다. API 등에서 `order`가 빠진 값은 `lora_2`, `lora_10`을 문자열이 아닌 숫자 순서로 fallback 정렬합니다.
- OFF인 LoRA, 파일명이 빈 LoRA, strength 0인 LoRA는 실행에서 제외합니다.

이 노드는 LoRA loader 자체를 장기 보관하지 않습니다. 현재 실행의 기본 model을 기준으로 매번 선택된 LoRA stack을 구성합니다.


8. PiD 업스케일 ON / OFF
PiD 업스케일은 선택 메뉴가 아니라 BOOLEAN 토글로 표시되며, 토글 라벨도 ON / OFF로 명시됩니다. 새로 삽입한 노드의 기본값은 항상 OFF입니다.

노드 UI 높이 동작:
- 새 노드는 PiD가 OFF여도 PiD ON 상태의 전체 설정이 들어갈 수 있는 높이를 초기 높이로 사용합니다.
- PiD OFF에서는 숨겨진 PiD 세부 설정만큼 `negative_prompt` 입력 영역이 자동으로 넓어지며, 노드 전체 높이는 줄어들지 않습니다.
- 다시 PiD ON으로 바꾸면 PiD 세부 설정이 같은 공간을 사용하고 `negative_prompt` 영역만 그만큼 줄어듭니다.
- 사용자가 노드 높이를 직접 늘린 경우 그 현재 높이가 새 기준이 됩니다. 이후 OFF/ON을 반복해도 늘린 전체 높이를 유지하면서 `negative_prompt` 영역과 PiD 설정 영역만 공간을 주고받습니다.
- 워크플로우를 전환했다가 다시 돌아오거나 저장한 워크플로우를 다시 열어도, 워크플로우에 저장된 노드 전체 크기를 최종 기준으로 복원하므로 사용자가 잡아둔 `negative_prompt` 영역의 세로 크기가 유지됩니다.
- 워크플로우 로드 중에는 저장된 크기 위에 PiD 레이아웃을 다시 계산해 덮어쓰지 않으며, 새 노드용 지연 설정 복원도 취소하여 뒤늦은 resize가 발생하지 않도록 합니다.
- 이 동작은 ComfyUI의 기본 multiline 레이아웃을 이용하며 별도의 반복 resize, ResizeObserver, `widget.y` 위치 조작을 사용하지 않습니다.

PiD OFF 실행 흐름:
1) 메인 diffusion model 로드
2) 메인 text encoder 로드
3) positive / negative conditioning 생성
4) 메인 latent 생성
5) 메인 KSampler 실행
6) 선택한 메인 VAE 로드
7) 메인 VAE decode → `Original Image` 생성
8) `PiD Image`에는 같은 원본 이미지를 그대로 전달
9) `Original Image` / `PiD Image` 출력

PiD OFF에서는 아래 PiD 전용 처리를 실행하지 않습니다.
- PiD 모델 검증
- PiD diffusion model 로드
- PiD Gemma / PixelDiT text encoder 로드
- PiD pixel_space VAE 로드
- PiDConditioning
- Context Windows (Manual)
- PiD KSampler

따라서 PiD 모델이 설치되어 있지 않아도 OFF 상태의 일반 이미지 생성은 정상적으로 사용할 수 있습니다.

PiD ON 실행 흐름:
1) 메인 diffusion model 로드
2) 메인 text encoder 로드
3) positive / negative conditioning 생성
4) 메인 latent 생성
5) 메인 KSampler 실행
6) PiD 설정을 한 번 검증
7) 현재 model_family에 맞는 PiD diffusion model 로드
8) PiD model에 Context Windows (Manual) 적용
9) PiD Gemma / PixelDiT text encoder 로드
10) `pixel_space` VAE 로드
11) positive prompt를 PiD CLIP으로 인코딩
12) 메인 sampled latent를 PiDConditioning에 전달
13) 4배 PiD target latent 생성
14) PiD KSampler 실행
15) pixel_space VAE decode
16) 필요하면 Lanczos 후처리 축소
17) `reinhard_lab / per_frame / strength 1.0` 자동 색상·명암 일치
18) `PiD Image` 생성
19) `Original Image` / `PiD Image` 출력

PiD ON에서도 `Original Image` 출력을 위해 메인 VAE decode는 수행됩니다. 다만 PiD 전용 경로는 `PiD Image` 출력을 위한 추가 처리입니다.


9. PiD 모델 계열 자동 제한
PiD 모델은 현재 model_family에 맞는 계열만 사용해야 합니다.

- Krea 2 → qwenimage PiD
- Anima → qwenimage PiD
- Qwen Image → qwenimage PiD
- Z-Image → flux1 PiD

Frontend는 PiD 파일명과 현재 model_family를 기준으로 후보를 필터링합니다.
Backend도 실행 전에 계열을 다시 검사합니다.

PiD 판별은 단순히 파일명 어딘가에 `pid` 세 글자가 들어있는지만 보지 않습니다. 경로/파일명의 독립된 `pid` 또는 `pixeldit` 토큰을 확인해 `rapid` 같은 일반 단어가 PiD로 잘못 잡히는 일을 줄입니다.

향후 Qwen-Image 2.1용 PiD 파일 이름에도 `qwenimage`가 들어갈 수 있으므로, `qwenimage21`, `qwen_image_2.1` 형태의 파일은 Krea 2 / Anima / Qwen Image의 PiD 후보에서 제외합니다.

일반 diffusion model을 PiD 모델 대신 자동 fallback하지 않습니다.


10. PiD sampler 설정
사용자에게 보이는 PiD 설정:
- PiD 모델
- PiD 샘플러
- PiD 스케줄러
- PiD 스텝
- PiD degrade sigma
- PiD 최종 배율

UI에 표시하지 않는 내부 고정값:
- PiD CFG = `1.0`
- PiD denoise = `1.0`

PiD 샘플러 기본값:
- `lcm`

PiD 스케줄러 기본값:
- `sgm_uniform`
- 현재 ComfyUI에 `sgm_uniform`이 없을 때만 `simple`, 그마저 없으면 첫 지원 scheduler로 fallback합니다.

PiD 최종 배율 기본값:
- `1(x4)`

사용자가 자유롭게 바꿀 수 있는 항목은 sampler / scheduler / steps / degrade sigma / 최종 배율입니다.
PiD sampler가 최초 노드 삽입 시 빈 값으로 남지 않도록 frontend에서도 `lcm` 기본값을 보정합니다.

PiD denoise는 일반적인 업스케일 사용에서 1.0으로 두는 경우가 많아 메뉴에서 제거했고, 내부적으로 항상 1.0을 사용합니다.


11. PiD degrade sigma
기본값은 `0.0`입니다.

일반적으로 메인 KSampler가 완전히 denoise한 정상 sampled latent를 PiD로 넘길 때는 0.0을 우선 사용합니다.
부분적으로 noisy한 latent를 의도적으로 넘기는 특수 상황에서는 사용자가 값을 조절할 수 있습니다.


12. PiD 최종 배율
표시는 아래와 같습니다.
- `1(x4)`
- `0.5(x2)`

`1(x4)`:
PiD가 만든 4배 결과를 그대로 출력합니다.

`0.5(x2)`:
PiD sampling 자체는 동일하게 4배 target에서 수행한 뒤, decode된 이미지를 Lanczos로 0.5 축소합니다.

따라서 `0.5(x2)`는 peak PiD sampling 메모리와 계산량을 x2 수준으로 줄이는 옵션이 아닙니다. 최종 저장/후처리 이미지 크기만 x2가 됩니다.


13. PiD latent format 자동 처리
latent_format은 사용자에게 표시하지 않습니다.

자동 규칙:
- Z-Image → `flux`
- Krea 2 / Anima / Qwen Image → `qwenimage`

잘못된 latent_format을 사용자가 직접 선택해 색상이나 처리 경로가 틀어지는 것을 막기 위한 내부 처리입니다.


14. PiD pixel_space VAE
PiD용 VAE 선택 메뉴는 제공하지 않습니다.
PiD는 내부에서 ComfyUI의 `pixel_space` VAE를 사용합니다.

PiD ON에서는 사용자가 선택한 메인 `vae_name`을 PiD decode에 사용하지 않습니다.


15. Context Windows (Manual)
PiD ON일 때만 PiD diffusion model에 `ContextWindowsManual`을 내부 적용합니다.

사용자 UI에는 Context Window 세부 옵션을 노출하지 않습니다.

현재 내부값:
- context_length = 2048
- context_overlap = 512
- context_schedule = standard_static
- context_stride = 1
- closed_loop = false
- fuse_method = pyramid
- freenoise = false
- cond_retain_index_list = 빈 값
- split_conds_to_windows = false
- latent_retain_index_list = 빈 값
- causal_window_fix = false

Context Window는 큰 PiD spatial 처리에서 한 번에 다루는 영역을 제한해 peak memory 사용을 낮추는 데 도움이 될 수 있습니다. overlap 때문에 총 연산량은 상황에 따라 늘 수 있으므로 모든 환경에서 무조건 더 빠르다는 의미는 아닙니다.


16. Context Window dim 자동 처리
`dim`은 사용자 UI에 표시하지 않습니다.

자동 규칙:
- width > height → dim = 3
- width < height → dim = 2
- width == height → dim = 2

즉:
- 가로형 → 3
- 세로형 → 2
- 정사각형 → 2

이 규칙은 PiD 출력에서 가로/세로에 따라 색상이 달라지는 문제를 피하기 위해 내부에서 자동 처리합니다.


17. 성능과 메모리 흐름
이 노드는 MODEL / CLIP / VAE 객체를 자체 전역 strong cache에 장기간 보관하지 않습니다.
통합 노드 내부에서 코어 Loader 함수를 호출하므로, Loader를 워크플로우에 별도 노드로 배치했을 때의 개별 그래프 출력 cache와는 구조가 다릅니다. 실행할 때마다 Loader 함수가 다시 호출될 수 있으며, 운영체제 파일 cache와 ComfyUI model-management가 실제 디스크 접근 및 offload 비용의 일부를 줄일 수 있습니다. 장기 strong cache를 두지 않는 이유는 오래된 MODEL 상태, LoRA 적용 상태, VRAM 점유 및 ComfyUI offload와의 충돌을 피하기 위해서입니다.

PiD OFF 효율:
- PiD 전용 heavyweight asset을 로드하지 않습니다.
- Context Window를 만들지 않습니다.
- PiD conditioning을 만들지 않습니다.
- 메인 VAE로 `Original Image`를 만들고, `PiD Image`에는 그 원본 이미지를 그대로 전달합니다.

PiD ON 효율:
- 메인 sampled latent를 직접 PiD로 넘깁니다.
- 원본 이미지(`Original Image`)를 얻기 위한 메인 VAE decode는 한 번 수행하지만, 그 이미지를 다시 encode해서 PiD로 넘기는 왕복 과정은 없습니다. PiD는 sampled latent를 직접 사용합니다.
- 메인 KSampler 완료 직후 더 이상 필요하지 않은 MODEL / CLIP / conditioning / 초기 latent의 로컬 참조를 해제해 PiD 모델 로드 전에 ComfyUI의 offload가 일하기 쉬운 상태로 만듭니다.
- PiD sampling과 VAE decode가 끝나면 메인 sampled latent 참조도 색상·명암 후처리 전에 해제합니다.
- PiD 설정 검증은 실행 전에 한 번만 수행합니다.
- Context Window는 PiD model에만 적용됩니다.
- 전역 cache clear나 강제 GPU 메모리 비우기를 호출하지 않으므로 다른 워크플로우의 모델 관리에 간섭하지 않습니다.
- 최종 `reinhard_lab` 색상·명암 일치는 모델, CLIP, VAE를 다시 로드하지 않으며 각 batch 프레임을 순서대로 처리합니다.
- Lab 변환은 최종 출력 해상도 전체를 처리하므로 PiD sampling과 별도로 약간의 처리 시간과 임시 메모리가 필요합니다. `1(x4)`가 `0.5(x2)`보다 이 후처리 비용도 큽니다.
- 색상·명암 일치 중에는 프레임 단위 진행 상태를 ComfyUI에 전달합니다.

Frontend 측에서는 모델/LoRA 목록 같은 문자열 목록만 캐시하며, 실제 MODEL/CLIP/VAE tensor 객체를 보관하지 않습니다.
Python 측에서도 반복적인 introspection 비용을 줄이기 위해 ComfyUI modern node의 클래스와 execute 시그니처 같은 가벼운 메타데이터만 캐시하며, MODEL/CLIP/VAE 객체는 캐시하지 않습니다.


18. 모델 계열별 설정 기억
Krea 2 / Z-Image / Anima / Qwen Image 각각의 마지막 실행 설정을 localStorage에 따로 기억합니다.

기억 대상 예:
- diffusion_model
- text_encoder
- vae_name
- width / height / batch_size
- steps / cfg / sampler / scheduler / denoise
- negative 설정
- LoRA 목록, 순서, 강도, ON/OFF
- PiD ON/OFF 토글
- PiD model / sampler / scheduler / steps
- PiD degrade sigma / 최종 배율

기억하지 않는 값:
- seed
- positive_prompt 내용

설정 기억은 위젯의 배열 위치가 아니라 이름을 기준으로 저장합니다. 기억 데이터 형식은 v2이며, 이전 v1 데이터에서 삭제된 `pid_denoise` 항목은 제거하고 알려진 밀림 오염값(`pid_degrade_sigma=1.0`)은 0.0으로 한 번 정리합니다.

새로 노드를 삽입한 경우에는 현재 model_family의 마지막 실행 설정을 자동 복원하되, `PiD 업스케일` 토글만은 안전한 기본값인 OFF로 시작합니다. PiD 모델·샘플러·스케줄러·스텝·degrade sigma·최종 배율 등 PiD 세부 설정은 기억값을 복원하므로 필요할 때 ON만 하면 바로 사용할 수 있습니다. 반대로 저장된 워크플로우를 열거나 복사한 노드는 그 워크플로우 안에 저장된 PiD ON/OFF 상태를 포함한 자체 값을 우선하며, 브라우저의 마지막 실행 설정으로 덮어쓰지 않습니다.

워크플로우 자체의 `widgets_values`는 ComfyUI가 위치 기반으로 저장하므로 별도 schema version을 기록합니다. 직전 버전의 `pid_denoise` 위치가 남아 있는 워크플로우를 열면 해당 한 칸을 자동 제거하고 `pid_degrade_sigma`와 `pid_output_scale` 위치를 정상화합니다.

실제 Queue 실행에 포함된 설정을 기준으로 저장합니다.

22. 문제 해결

22-1. PiD 샘플러가 비어 있음
현재 버전은 `lcm`을 기본값으로 설정하고 frontend에서도 빈 값일 경우 다시 보정합니다.
브라우저에 이전 JS가 캐시되어 있다면 Ctrl+F5를 하십시오.

22-2. PiD 모델이 없음
PiD OFF에서는 정상 이미지 생성이 가능합니다.
PiD ON에서는 현재 모델 계열에 맞는 PiD 모델이 필요합니다.

22-3. PiD Gemma encoder가 없음
PiD ON에서는 화면에서 선택한 메인 text encoder와 별도로 PixelDiT용 `gemma_2_2b_it_elm` 계열 text encoder가 필요합니다. 화면에서 Qwen3-VL 계열을 선택한 것만으로는 PiD 전용 Gemma encoder가 준비된 것이 아닙니다.

확인 순서:
1) `gemma_2_2b_it_elm_fp8_scaled.safetensors` 또는 `gemma_2_2b_it_elm_bf16.safetensors`가 있는지 확인합니다.
2) 파일을 `ComfyUI/models/text_encoders/` 폴더에 둡니다. Windows Portable은 보통 `ComfyUI_windows_portable/ComfyUI/models/text_encoders/`입니다.
3) ComfyUI를 재시작하거나 모델 목록을 새로고침합니다.
4) PiD를 다시 실행합니다.

노드는 FP8 scaled를 먼저 찾고, 없으면 BF16 또는 파일명에 `gemma_2_2b_it_elm`이 포함된 후보를 자동으로 선택합니다. PiD가 OFF이면 이 파일을 검사하거나 로드하지 않습니다.

22-4. PiD 결과 색상이 달라짐
현재 통합 노드는 Context Window dim을 가로형 3, 세로형/정사각형 2로 자동 지정합니다.
PiD ON에서는 업스케일 결과에 원본을 참조하는 `reinhard_lab / per_frame / strength 1.0` 색상·명암 일치가 자동 적용됩니다. 이 방식은 원본 픽셀을 덮어쓰지 않으므로 PiD의 공간 구조와 디테일은 대체로 유지됩니다. 다만 색상·명암을 통계적으로 일치시키는 방식이므로 모든 픽셀이 원본과 완전히 같아지지는 않으며, 강한 채도·극단적인 명암·색 영역 clipping이 있는 일부 이미지에는 육안 차이가 남을 수 있습니다.
그래도 눈에 띄는 색상 변화가 있다면 실제 사용 중인 PiD checkpoint, scheduler, sampler, ComfyUI 버전을 함께 확인하십시오.

22-5. PiD가 너무 느리거나 VRAM 부족
- base width / height를 줄여 확인
- batch_size를 낮춰 확인
- PiD checkpoint 종류 확인
- Context Window는 내부 적용되지만, 0.5(x2)도 PiD sampling은 x4 target에서 이루어진다는 점에 주의

22-6. 모델 변경 후 PiD 모델이 달라짐
model_family에 맞지 않는 PiD 모델 사용을 막기 위해 PiD 후보를 qwenimage / flux1 계열로 자동 필터링합니다.

22-7. LoRA가 보이지 않음
노드 우클릭 메뉴의 `모델·LoRA 목록 새로고침`을 사용하거나 ComfyUI 모델 목록을 새로고침하십시오.
정상적으로 조회했지만 파일이 하나도 없을 때는 "LoRA 파일 없음"으로 안내하고, ComfyUI object_info 조회 자체가 실패한 경우에는 "LoRA 목록을 읽지 못했습니다"라는 별도 안내를 표시합니다.

22-8. LoRA 강도 입력창이 열리지 않음
일부 프런트엔드 조합에서 사용할 수 있는 prompt dialog API가 모두 없으면, 이전처럼 아무 반응 없이 끝나지 않고 현재 프런트엔드에서 강도 입력창을 열 수 없다는 알림을 표시합니다.

22-9. 원본/PiD 결과 비교
제공 예제는 `Original Image`를 Preview Image에 연결합니다. PiD 결과를 확인하려면 `PiD Image` 출력을 Preview Image나 Save Image에 연결하십시오. 원본과 PiD 결과를 나란히 비교하려면 이미지 비교 노드의 두 입력에 `Original Image`와 `PiD Image`를 각각 연결하면 됩니다.


23. 최종 요약
Ultra Tools Image + PiD는 이미지 생성과 선택적 PiD 업스케일을 한 노드에서 처리하는 `Original Image / PiD Image` 이중 출력 노드입니다.

핵심 원칙:
- 기본 출력은 `Original Image` / `PiD Image` 두 개
- PiD 토글은 OFF가 기본
- OFF일 때 `PiD Image`는 원본 passthrough이며 PiD 실행 경로 완전 미사용
- ON일 때 메인 sampled latent를 직접 PiD에 전달
- PiD CFG 1.0 고정
- PiD sampler / scheduler / steps 사용자 조절
- PiD denoise 내부 1.0 고정
- degrade sigma 기본 0.0
- latent_format 자동
- pixel_space VAE 자동
- Context Window 자동
- dim 가로 3 / 세로·정사각 2 자동
- 1(x4) / 0.5(x2) 최종 출력 선택
- PiD ON에서 `reinhard_lab / per_frame / strength 1.0` 색상·명암 일치 자동 적용
- heavyweight runtime 객체의 자체 장기 cache 없음


24. SageAttention
- SageAttention은 메인 이미지 생성 MODEL에만 선택적으로 적용하는 고급 가속 옵션입니다.
- 기본값은 OFF입니다.
- OFF에서는 KJNodes의 Patch Sage Attention KJ 노드를 조회하거나 호출하지 않으며 sageattention 라이브러리도 import하지 않습니다. 따라서 KJNodes가 없거나 SageAttention을 사용할 수 없는 환경에서도 기존 이미지 생성 경로에 관여하지 않습니다.
- ON에서만 설치된 ComfyUI-KJNodes의 Patch Sage Attention KJ를 내부 호출합니다. 내부 설정은 sage_attention=auto, allow_compile=False로 고정합니다.
- KJNodes가 없거나 SageAttention/CUDA/PyTorch 환경이 맞지 않으면 ON 실행에서만 명확한 오류를 표시합니다.
- 적용 순서는 기본 MODEL -> LoRA -> 모델별 ModelSamplingAuraFlow(해당 모델만) -> SageAttention -> 메인 KSampler입니다.
- PiD 업스케일 MODEL에는 SageAttention을 적용하지 않습니다. PiD는 기존 Context Windows (Manual) 경로를 그대로 사용합니다.
